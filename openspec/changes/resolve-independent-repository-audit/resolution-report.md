## 4. Backup protocol, rollout and rollback

The local SQLite schema remains 25. New durable capture/legacy-cutover keys are local operational app_meta values, not account backup entities. Capture holds one coherent SQLite transaction and performs no network I/O. Captured chunks, owner and exact outbox revisions survive restart. Publication acknowledges only those revisions, leaving newer edits pending.

Three additive migrations form the reviewed namespace, in order:

1. `20261018000000_add_backup_generation_protocol.sql`.
2. `20261019000000_fix_backup_generation_publication.sql`.
3. `20261019162537_verify_and_reserve_backup_generations.sql`.

The final file corrects earlier contracts rather than editing applied predecessor migrations. The owner-scoped reservation and publication journal have RLS. Publication is RPC-only; privileged RPCs pin search_path and fully qualify objects. Content is immutable, owner-scoped, and retained across head changes. Serial head checks cover both first-publication races and later CAS conflicts. No automatic production garbage collection is enabled.

Before a rollout, independently review and apply these migrations to an authorized disposable Supabase project, run the qualification below through hosted Auth/PostgREST, inspect privileges/locale/request limits, and certify old/current-client recovery. Deploy server capability support before enabling this client. Without the advertised protocol, remote backup pauses and preserves local pending writes and existing recovery bytes; local use continues. Do not silently disable the capability check.

Rollback must retain the additive generation tables and immutable recovery history. Prefer stopping remote publication while preserving pending local capture/outbox work. An old client may continue changing legacy mutable rows, but new Restore reads the immutable head; those later old-client writes do not automatically become part of that head. Retiring or replacing a stale unpublished capture requires an explicit owner-reviewed reconciliation of the newer remote point and retained local data. Do not delete app_meta captures to hide a conflict or roll back the schema underneath a published generation.

Legacy V1 partial restore remains available. Automatic cutover of a manifestless partial account is deliberately refused because completeness cannot be certified. Historical V2 scope-6/7 snapshots use their frozen entity/settings checksums before conversion. Unknown versions and corrupt published content fail closed. Recurrence association inheritance remains `SPEC_AMBIGUITY`; no unrequested product policy was invented.
