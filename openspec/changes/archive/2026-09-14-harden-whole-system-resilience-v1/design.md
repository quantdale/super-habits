### D1 — Adopt the inherited uncommitted wave instead of discarding it

At campaign start the worktree held a coherent, uncommitted read-path
hardening set (35 modified files + `tests/integration/hotPathIndexes.test.ts`):
migration 24 hot-path range indexes, concurrent Overview/Workout/backup reads,
an existence probe replacing a week-of-rows materialization, single-round-trip

that skips redundant restore-preview refreshes. It aligns with Workstream A's
index/query-shape audit and long-session goals. Decision: validate it on its
own merits (typecheck + full Vitest first), audit each change against the
governing invariants, then land it as early campaign work with the required
broader gates. Never reset unrelated work; if any piece fails audit, repair or
revert that piece with recorded evidence.

### D2 — Soak lane asserts trends against existing contracts

Resource ceilings derive from D14/product responsiveness contracts and
repeated known-good baselines. The soak lane drives behavior through real
product interactions (section transitions, refreshes, CRUD, focus cycles,
reload/foreground) in Playwright-owned browser contexts with service workers
blocked per the established simulation isolation, emits machine-readable
samples, and requires two clean post-fix fresh runs for acceptance.

### D3 — Migration laboratory uses synthetic committed fixtures

Representative historical databases are generated by repository-safe builders
at meaningful boundaries (v6-era todos ordering columns, migration-5 date-key
cutover mix, outbox/owner additions, planning entities, habit lifecycle,
Gym V2 tables). Coverage claims say "synthetic migration matrix covered";
real-corpus gaps #5/#6 stay registered with narrowed wording only where
fixtures genuinely move evidence.

### D4 — Recovery fault injection proves final authoritative state

Every injected failure (corrupt manifest/checksum, missing sections, duplicate
IDs, invalid enums/dates, tombstones, owner mismatch, partial settings,
unsupported versions, interrupted import via test seams, reattempt/repeat)
asserts the resulting SQLite state, not just an error message. Live Supabase
stays untouched; mocked adapters and dist-sync lanes carry remote-boundary
proof.

## Risks / Trade-offs

- Soak lanes are host-sensitive → prefer bounded growth/stabilization trend
  assertions over absolute numbers; record environment context per run.
- Fixture generation risks encoding current assumptions into historical
  fixtures → builders derive shapes from the actual historical migration
  blocks in `core/db/client.ts`, not from `schema.sql` snapshots.
- Long-running lanes cost time → run them after cheaper gates are green;
  keep every artifact path reproducible.
