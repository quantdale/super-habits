# UI/UX Inspiration Research

**Research date:** 2026-08-21  
**Method:** official product sites/help centers/store descriptions were used as the primary sources. The purpose is to identify transferable product-design patterns, not to reproduce another product's trade dress.

---

## 1. Research rule: copy the principle, not the pixels

For every inspiration below, Super Habits may borrow:

- interaction principles;
- information hierarchy;
- feedback-loop structure;
- common UI conventions;
- accessibility and motion guidance;
- conceptual approaches to reducing friction.

Super Habits should **not** copy:

- exact layouts;
- illustrations;
- proprietary icons;
- character designs;
- wording;
- brand palettes;
- distinctive animation sequences;
- reward assets;
- screenshots or visual compositions closely enough to create a clone.

The desired result is recognizably Super Habits.

# 2. Avocation

Official source: <https://avocation.app/>

## Relevant product pattern

Avocation positions habit formation through a deliberately simple, friendly, visually approachable tracker rather than a dense productivity dashboard. Its product identity connects repeated behavior with a growth metaphor and uses illustration to make routine check-ins feel less mechanical.

## What Super Habits should transfer

### A. Habits deserve emotional identity

Habit check-in is repeated every day. A plain checkbox can be functionally correct but emotionally flat. Super Habits can make completion feel meaningful through:

- subtle growth;
- rounded friendly shapes;
- calm illustration;
- short reinforcing feedback;
- visible accumulation over days.

### B. Education should be lightweight

Behavior-change guidance works better as small contextual ideas than as a permanent block of instructional text. Use optional tips in onboarding, habit creation, and insights.

### C. Simplicity before analytics

Daily habit action should be the first layer; statistics belong in detail/insights.

## What not to transfer literally

- plant artwork;
- identical growth stages;
- identical habit-card layout;
- same colors/type treatment;
- identical onboarding illustrations.

## Super Habits adaptation

Create an original “Momentum” visual system that can receive progress from habits and other modules. This prevents Habits from becoming a visual mini-app disconnected from Focus/Workout/etc.

# 3. Forest

Official sources:

- <https://www.forestapp.cc/>
- <https://apps.apple.com/us/app/forest-focus-for-productivity/id866450515>

## Relevant product pattern

Forest's core idea makes otherwise invisible focus time visible as a growing object and then accumulates completed sessions into a larger visual history. Current official descriptions also emphasize focus statistics, unlockable trees/soundscapes, group focus, achievements, app-blocking/digital-wellbeing features, and real-tree planting integrations depending on tier/platform.

## What Super Habits should transfer

### A. Visualize elapsed effort, not just elapsed time

A timer number tells users what is happening. A gradually developing visual gives the session emotional continuity.

For Super Habits Focus:

- grow an original visual artifact during the timer;
- tie growth directly to elapsed session progress;
- keep it subtle enough that it does not itself become a distraction.

### B. Accumulate completed sessions into history

A week of focus can become a visual collection in addition to a conventional minutes chart. This makes long-term consistency easier to feel.

### C. Reward meaningful milestones

Unlockable cosmetic variations can be healthy if they correspond to genuine focus milestones and do not rely on random reward schedules.

## What Super Habits should not transfer

Forest's punitive emotional mechanic — where interruption can damage/kill the growing tree — should not be copied literally. Super Habits should prefer:

- pause;
- partial completion where product semantics allow;
- neutral abandon confirmation;
- “welcome back” recovery.

The product should encourage focus without making interruption feel like damage to a virtual pet.

# 4. Macro Sync by Macros Inc

Official sources:

- <https://macrosinc.net/macro-sync/>
- <https://apps.apple.com/us/app/macro-sync/id6475427404>

## Relevant product pattern

Macro Sync is built around frequent food logging and daily nutrition targets. Official descriptions highlight food search/database functionality, barcodes, calorie/macronutrient tracking, serving sizes, custom goals, and related logging/support features.

## What Super Habits should transfer

### A. Logging speed is the feature

Nutrition apps are opened several times a day. Every unnecessary field compounds into frustration.

Prioritize:

- recent/frequent foods;
- sensible default serving values;
- meal grouping;
- quick add;
- search that prioritizes likely results;
- immediate return to the daily summary.

### B. Daily state belongs above history

The user usually needs “where am I today?” before “what happened last month?”

Top hierarchy:

1. calories;
2. core macros;
3. meals/logging;
4. secondary trends.

### C. Update totals immediately

Logging should visibly update remaining/target values without making the user navigate away.

## What not to transfer

- identical macro-ring layout;
- exact color encoding;
- branded rewards/badges;
- database or coaching claims not supported by Super Habits.

## Ethical adaptation

Nutrition is especially sensitive to shame. Over-target states should remain neutral and factual. Avoid red failure screens or emotionally loaded language.

# 5. Todoist

Official sources:

- <https://www.todoist.com/features>
- <https://www.todoist.com/help/articles/use-task-quick-add-in-todoist-va4Lhpzz>

(Official regional/testing pages may expose newer versions of the same documentation; implementation should re-check the canonical Todoist docs if researching a specific current behavior.)

## Relevant product pattern

Todoist has spent years optimizing fast task capture and a calm hierarchy around tasks, projects, priorities, dates, labels, and quick entry. Its Quick Add model is particularly relevant to Super Habits.

## What Super Habits should transfer

### A. Capture should be faster than organization

A user must be able to create a basic task before deciding every metadata field.

### B. Metadata should be visually subordinate

Task title is primary. Date/project/priority/recurrence are useful context, not equal-weight visual objects.

### C. Progressive disclosure protects clarity

Power features can exist without showing every control all the time.

### D. Clear completion state

Task completion should remove cognitive weight from the current list quickly.

## Super Habits adaptation

Keep Super Habits' broader cross-module context, but make the task row itself boring in the best sense: predictable, fast, and easy to scan.

# 6. TickTick

Official sources:

- <https://ticktick.com/features?language=en_US>
- <https://ticktick.com/about>

## Relevant product pattern

TickTick is unusually relevant because its official feature set combines tasks, calendar views, habits, Pomodoro/focus, statistics, reminders, and personalization inside one product. That is structurally closer to Super Habits than a standalone todo app.

## What Super Habits should transfer

### A. Many modules can still share one mental model

The important lesson is not any one TickTick screen. It is that tasks, calendar/planning, habits, and focus can use shared navigation, typography, forms, and statistics without feeling identical.

### B. Capture/access can exist in many contexts

TickTick emphasizes quick ways to add tasks across surfaces. Super Habits should similarly make Quick Capture globally available.

### C. Shared statistics matter

Cross-feature progress can be more useful than siloed charts, provided the metrics remain understandable.

### D. Personalization is secondary to structure

Themes and customization enrich a stable UI; they should not substitute for a stable UI.

## Super Habits differentiation

Super Habits extends deeper into workout and nutrition, so its design system must handle both productivity density and health logging without breaking cohesion.

# 7. Hevy

Official sources:

- <https://www.hevyapp.com/>
- <https://www.hevyapp.com/features/>
- <https://help.hevyapp.com/hc/en-us/articles/33106320824727-Everything-You-Need-to-Know-About-the-Hevy-App-2025-Features-Guide>

## Relevant product pattern

Hevy's public feature descriptions emphasize workout logging, routine planning, automatic rest timers, progress tracking/graphs, workout history, and social features. The most transferable UI principle is presenting the information needed **during the set** instead of making the user navigate through analytics.

## What Super Habits should transfer

### A. Previous performance is input context

When logging today's set, show useful prior values close to today's fields.

### B. Rest timer should be automatic but non-blocking

The timer supports the workout. It should not hijack the interface.

### C. Session mode should be utilitarian

During a workout, reduce decorative content and prioritize:

- exercise;
- set values;
- completion;
- rest;
- next action.

### D. PR feedback should be local and meaningful

A personal record is worth celebrating, but the user may be mid-session. Use concise celebration near the relevant set and summarize it at the end.

## What not to transfer

- social feed as a mandatory core loop;
- exact set-table styling;
- identical badges/PR visuals;
- exact routine-card hierarchy.

# 8. Apple Human Interface Guidelines

Official sources:

- Accessibility: <https://developer.apple.com/design/human-interface-guidelines/accessibility>
- Motion: <https://developer.apple.com/design/human-interface-guidelines/motion>

## Relevant guidance

Apple's current HIG emphasizes:

- familiar and consistent interactions;
- sufficiently sized controls;
- multiple ways to perceive important information;
- support for system accessibility preferences;
- purposeful, brief motion;
- avoiding gratuitous animation;
- reducing large/repetitive movement when Reduce Motion is enabled.

Apple lists a 44×44pt default control size for iOS/iPadOS, while noting smaller minimums in specific platform guidance. Super Habits should use approximately 44×44 as its normal frequent-touch target rather than designing to the smallest allowed exception.

## Super Habits application

- Build accessibility behavior into shared primitives.
- Let system Reduce Motion override ambient/growth effects.
- Use haptics as supplemental feedback, never as the only feedback.
- Keep animations cancelable/non-blocking.

# 9. WCAG 2.2

Official sources:

- Standard: <https://www.w3.org/TR/WCAG22/>
- New in WCAG 2.2: <https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/>
- Target Size (Minimum): <https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html>
- Focus Appearance: <https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html>

## Relevant guidance

WCAG 2.2 adds criteria especially relevant to Super Habits Web:

- focus must not be obscured;
- dragging needs alternatives in applicable cases;
- pointer targets have minimum sizing/spacing expectations;
- visible focus must remain clear.

WCAG 2.5.8 defines a 24×24 CSS-pixel minimum target size with specified exceptions. Super Habits should generally exceed this for primary controls and use the larger mobile target guidance defined in the Design DNA.

## Super Habits application

- Explicit keyboard focus rings on web.
- Swipe/drag operations have button/menu equivalents.
- Sticky controls do not cover focused content.
- Charts provide text alternatives/summaries.
- Completion state is not encoded by color alone.

|---|---|---|---|
| Avocation | Friendly growth-based habit feedback | Habits, onboarding, Momentum | Plant art / exact layout |

# 11. Derived design thesis

The sources converge on one useful strategy for Super Habits:

> **Keep the operational layer extremely simple, then make accumulated progress emotionally rich.**

That means:

- Todos: simple list, satisfying completion.
- Habits: simple check-in, rich continuity.
- Focus: simple timer, rich accumulated visual history.
- Workout: simple set logging, rich progress/PR history.
- Calories: simple logging, rich daily/trend understanding.
- Overview: simple next action, rich cross-feature reflection.

This is the key safeguard against a “gamified” redesign becoming cluttered. The user should never have to fight the fun layer to perform the useful action.

# 12. Research maintenance

Before implementing a major pattern inspired by an external product:

1. re-check the official source because products evolve;
2. document the interaction principle in plain language;
3. verify the same problem exists in Super Habits;
4. design an original solution consistent with Warm Momentum;
5. test it against the Design DNA and accessibility contract;
6. reject it if it adds visual novelty without improving clarity, speed, motivation, or understanding.
